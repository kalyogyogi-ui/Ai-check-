### 6.4 Tips for standing out in a proposal

1. **Open with the regulatory clock.** NIST FIPS 203/204/205 (Aug 2024),
   HQC selected (Mar 2025), CNSA 2.0 (full mandate 2033), EU PQC
   roadmaps (first deadlines 2026), India CERT-In quantum-safe
   advisories. Editors track regulatory clocks because they predict bulk
   enterprise sales.
2. **Show comp-title math.** Cite 3–5 books per Phase 1 list with sales-
   rank proxies (Amazon BSR, O'Reilly platform views) and explain *why
   your book differs in audience, level, or format*.
3. **Lead with a *working* GitHub repo skeleton.** Even a `README.md`,
   chapter folders, and one runnable notebook in Colab makes a proposal
   tower above 95% of submissions for Packt/Apress/Manning.
4. **Endorsements** for Wiley/CUP/OUP/MIT — one or two short emails from
   recognizable names (PQShield, IBM Quantum, EF, NIST, Indian IITs)
   change the acceptance odds.
5. **Series alignment.** Don't pitch a generic title — pitch *into* a
   series: Manning "in Action" or "Grokking"; Apress "Beginning / Pro /
   Practical"; Packt "Hands-On / Mastering / Cookbook"; No Starch
   "Serious …"; Springer Briefs; CRC "Smart Engineering Systems".
6. **Schedule realism.** Promise weekly chapter cadence with two-week
   buffers. Most authors miss deadlines — a credible Gantt chart
   differentiates.
7. **Audience-size math.** Reference Stack Overflow tags, GitHub repo
   stars (Qiskit, liboqs, ethers.js), and Coursera/edX enrollments — quantify
   addressable market.
8. **Hands-on hook.** State exactly what readers *build* (a wallet, a
   chain, a rollup) and how long each lab takes.
9. **Risk plan.** Acknowledge that the field moves fast and describe how
   you'll absorb changes (e.g., NIST round-4 outcomes, EIP changes) into
   the manuscript and into the GitHub companion post-launch.
10. **Trust posture.** Cite arXiv preprints (e.g., NIST PQ-Crystals
    documentation; Vitalik's "How to hard-fork to save most users'
    funds in a quantum emergency" 2024 post; QuIA milestones; Wehner
    stack papers); auditors trust authors who read primary sources.

### 6.5 Risk and mitigation summary

| Risk | Mitigation |
|---|---|
| NIST round-4 or follow-on selections change algorithm portfolio | Build code companion around `liboqs`/`pq-crystals` so swapping is trivial; commit to "v2" patch chapter |
| Ethereum / Bitcoin PQ roadmaps diverge | Cover both via account-abstraction and BIP-360; keep chapter 8 modular |
| Quantum hardware "winter" delays Q-day | Frame as *risk-management* book, not as Q-day countdown; HNDL drives demand regardless |
| Competing edited handbook from IGI/CRC | Differentiate via single-author voice + Python labs + GitHub |
| Author fatigue on 14–24 mo cycle | Publish first with Packt/Apress (10 mo) then optionally upmarket second edition with Manning/No Starch |
